# Tokensanity: implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Tokensanity option (`off` / `dungeons` / `overworld` / `all`). The chosen Gold Skulltulas become fill locations, and their tokens go into the item pool.

**Architecture:**
- `fill.place` keeps returning `Hash -> content`, now also for the Skulltula Hash values.
- `patch.write_mod` translates a Skulltula's content into an actor that can be dropped. That actor is either an existing `Obj_*`, or a wrapper `Obj_Rando_<content>`, a copy of `Obj_Token_Gold` generated by the new module `wrappers.py`.
- `wrappers.py` adds the wrappers' RSDB rows and RSTB entries.
- Skulltulas are mapped to OoTR locations with `randomizer/data/gs_map.json`.

**Tech Stack:** Python 3 (standard library), `unittest`, own formats in `randomizer/formats/`.

**Spec:** `docs/superpowers/specs/2026-11-10-tokensanity-design.md`. Phase 1 has passed (`docs/test-batch-15.md`). This plan covers phases 2 and 3.

## Global Constraints

- The `.nup` is never written to and commits never include game files. Tests that read the game use `OOT_NUP` and carry `@unittest.skipUnless(NUP_PATH, 'OOT_NUP not defined')`. For one-off checks: `OOT_NUP="<path to your .nup file>"` (read only).
- Tests are run with `python -m unittest` from the repository root.
- Commits carry no attribution lines.
- With `tokensanity='off'`, the generated mod and the spoiler log are byte-for-byte identical to those from before this plan, and no `RSDB/` file is written.
- Option values, exactly: `TOKENSANITY = ('off', 'dungeons', 'overworld', 'all')`. Default `'off'`.
- Remake token: `TOKEN = 'Obj_Token_Gold'`. In OoTR's logic it is `'Gold Skulltula Token'`.
- Wrapper prefix: `'Obj_Rando_'`, followed by the content as is (for example `Obj_Rando_Item_Hookshot`).
- The Bomb Bag (`Item_BombBag_Small`) stays fixed. It is not touched, because it is no longer eligible.
- Key items do not go to the `NO_KEY_TARGET_ZONES` zones, nor to their Skulltulas.
- Interface and spoiler log texts in English.

## Review Focus

1. **Hash duplicated in two Banc files** (14 child/adult or "Alternative" Skulltulas): `write_mod` has to change all its copies, and the fill has to count them only once. Test in task 5.
2. **Chest content that cannot be dropped** (what `wrappers.can_wrap` rejects): it never ends up in a Skulltula. If that leaves fewer valid contents than Skulltulas, the error is clear and in English. Test in task 4.
3. **Skulltula without `Dynamic`** (none has it set): `write_mod` creates the dict and the key. Test in task 5.
4. **Same content in several Skulltulas** (for example `TBox_Rupee_Red` in 10): a single wrapper or actor is generated, with no duplicate RSDB rows. Test in task 2.
5. **The same seed with a different `tokensanity`** gives different fills. With `off` it gives exactly the previous fill, because the RNG key does not change. Test in task 4.

- Produces: `Rstb.add(path: str, size: int) -> None`. Inserts `[crc32(path), size]` into `_crcs` keeping the crc order. Raises `ValueError` if the crc already exists.

The `write` algorithm is tested in the `sarcw.py` spike (session scratchpad). If it cannot be read, this is the format:
- `SARC` header of 0x14 bytes, LE, BOM `0xFEFF`, version `0x0100`;
- `SFAT` with hash multiplier `0x65`;
- nodes sorted by `h = (h*0x65 + c) & 0xFFFFFFFF` over the name bytes;
- attribute `0x01000000 | (name_offset // 4)`;
- `SFNT` with names terminated in `\0` and padded to 4;
- data start aligned to `data_align`, and each file aligned to `align`.

### Task 2: Wrappers (`randomizer/wrappers.py`)

**Files:**
- Create: `randomizer/wrappers.py`
- Test: `tests/test_wrappers.py`

**Interfaces:**
- Consumes: `sarc.read`, `sarc.write`, `Rstb.add`, `Rstb.get`, `Rstb.set`, `byml.load` and `byml.dump`, and `GameData` (`.nup`, `.codec`).
- Produces:
  - `WRAPPER_PREFIX = 'Obj_Rando_'`
  - `RSDB_TABLES = ('ActorInfo', 'GameActorInfo', 'PouchActorInfo')`, with path `f'RSDB/{t}.Product.111.rstbl.byml.zs'`
  - `pouch_rows(game: GameData) -> frozenset[str]`: the `__RowId` values of `PouchActorInfo`.
  - `drop_actor(content: str, rows: frozenset[str]) -> str`. It applies the first rule that fits:
    1. `content` starts with `Obj_` and is in `rows`: returns `content`.
    2. It starts with `TBox_` or `Tbox_`, and `'Obj_' + rest` is in `rows`: returns `'Obj_' + rest`.
    3. In any other case: returns `WRAPPER_PREFIX + content`.
  - `can_wrap(game: GameData, content: str) -> bool`: True if `Pack/Actor/{content}.pack.zs` exists, if its ActorParam (`Actor/{content}.engine__actor__ActorParam.bgyml`) has the five refs `ActorNameRef`, `ModelInfoRef`, `AnimationRef`, `PouchContentRef` and `GameParameterTableRef`, and if `content` is in `PouchActorInfo` and in `ActorInfo`.
  - `build_wrapper_files(game: GameData, contents: Iterable[str], rstb: Rstb) -> dict[str, bytes]`. It does the following:
    - For each distinct content that needs a wrapper (according to rule 3 of `drop_actor`), it generates a compressed `Pack/Actor/Obj_Rando_<c>.pack.zs`.
    - It generates the three RSDB tables, compressed and with their new rows.
    - It modifies `rstb` in place: `add` for each pack and `set` for each table.
    - It returns `{}` if no wrapper is needed.
    - If any content fails `can_wrap`, it raises `ValueError` with its name.

The recipe is the one in spec §3, as is. The reference spike is `lote15.py` (`clone` with `autoget=True` and no grafts). Specific points:
- **Pack contents.** Base: the `Obj_Token_Gold` pack without its ActorParam. The five refs are replaced with those of the content. The files from the content's pack that are missing are added, except those in `Actor/`.
- **`PouchContentParam`.** A copy of the content's with `DefaultAutoGet: True`, saved in `Component/PouchContentParam/Obj_Rando_<c>.game__component__PouchContentParam.bgyml`.
- **ActorParam.** The new one is `Actor/Obj_Rando_<c>.engine__actor__ActorParam.bgyml`, with the same BYML version as the token's.
- **Pack format.** `sarc.write(files, 8, 0x20)`. Pack RSTB: `len(raw) + 0x1000`.
- **`ActorInfo`.** A copy of the `Obj_Token_Gold` row with these changes:
  - new `__RowId`;
  - `ActorName = content_row.get('ActorName', content)`;
  - the keys `FmdbName`, `ModelProjectName`, `AnimationResources`, `ModelAabbMax` and `ModelAabbMin`, copied from the content if it has them;
  - `InstanceHeapSize` and `PreActorRenderInfoHeapSize` = `max(token, content) + 0x10000`.
- **`GameActorInfo`.** A copy of the token's row, plus the content's `ModelVariationAnims` if it has them.
- **`PouchActorInfo`.** A copy of the content's row with the new `__RowId`.
- **Table order.** Sorted by `__RowId`, using Python string order.
- **RSTB of each table.** `len(new) + (original_rstb - len(original)) + 0x1000`.

What the mapping does:
- **First, by zone.** Zones are the second segment of the Banc path. The number of Skulltulas per zone matches OoTR. The `HyruleField` Banc also contains those of "LH" (Lake Hylia) and "LLR" (Lon Lon Ranch). The OoTR ones are the 100 locations with `vanilla_item == 'Gold Skulltula Token'` that exist in `World` (without MQ). Their region and rule, in `randomizer/logic/ootr/World/*.json`, give the age and whether it is night (`at_night`), soft soil (bean) or grotto.
- **Within each zone,** they are told apart by:
  - `Enemy_Skulltula_Gold_Nocturnal` and `Enemy_Skulltula_Gold_IsMagicBeanSoil`;
  - the child or adult Banc (or both);
  - `DefaultDungeonRoomIndex` in dungeons;
  - the position relative to the chests of the same zone already mapped in `location_map.json`.
- **If a zone has Skulltulas with the same requirements in the logic,** swapping them changes nothing in the logic. Those can be marked `confirmed` with the note "identical requirements". The other doubtful ones go as `guessed`.
- **`dungeon` is True** if the zone is one of the 10 dungeons: Deku Tree, Dodongo's Cavern, Jabu-Jabu, Forest, Fire, Water, Shadow, Spirit, Well and Ice Cavern.

### Task 4: Fill with Skulltula locations

**Files:**
- Modify: `randomizer/fill.py`
- Test: `tests/test_fill.py`

**Interfaces:**
- Consumes: `SkulltulaActor`, `GsEntry` and `load_gs_map` (task 3).
- Produces:
  - `TOKENSANITY = ('off', 'dungeons', 'overworld', 'all')`, `TOKEN = 'Obj_Token_Gold'`, `OOTR_TOKEN = 'Gold Skulltula Token'`.
  - `Settings.tokensanity: str = 'off'`, as a new field at the end.
  - `place(chests, loc_map, world, settings, skulltulas: list[SkulltulaActor] = (), gs_map: dict[int, GsEntry] | None = None, gs_forbidden: frozenset[str] = frozenset()) -> dict[int, str]`. The dict contains all the chest Hash values, as today, plus the Hash values of the Skulltulas that enter, with their remake content (`'Obj_Token_Gold'`, `'TBox_Rupee_Red'`, `'Item_Hookshot'`…). Skulltulas that do not enter do not appear.
  - `gs_sites(skulltulas, gs_map, mode: str) -> list[int]`. It returns the Hash values that enter according to the mode:
    - `dungeons`: those with `dungeon` True;
    - `overworld`: those with it False;
    - `all`: all the mapped ones;
    - `off`: none.

    No duplicates and sorted.

Changes in the algorithm:
- **RNG key.** `_settings_key` only includes `tokensanity` if it is different from `'off'`, so that with `off` everything stays the same.
- **Invalid mode.** If `settings.tokensanity` is not in `TOKENSANITY`, `FillError` is raised.
- **Eligible locations.** Those of the Skulltulas that enter are eligible, and their original content is `TOKEN`. The internal `Hash -> OoTR location` map joins `loc_map` (chests) and `gs_map`. `base` puts `FILLER` at those locations, just like with chests.
- **Tokens in `fixed`.** `_fixed` puts `OOTR_TOKEN` at the location of any location with `TOKEN`, in addition to the key items. That way `can_beat` counts the tokens.
- **Forbidden zones.** `no_key` also includes the Skulltulas whose Banc zone is in `NO_KEY_TARGET_ZONES`.
- **Distribution of the rest.** Non-key content is shuffled as today, but:
  - free Skulltula locations are filled first with the first shuffled contents that are not in `gs_forbidden`;
  - what remains, including the forbidden contents, goes to the free chests in shuffled order;
  - if there are not enough allowed contents for all the free Skulltulas, `FillError('Not enough droppable items for the Skulltulas')` is raised.
- **Bomb Bag.** Unchanged (it stays outside what is eligible).
- **World.** It is built outside; `generate` passes it `tokensanity` (task 6). The fill does not modify it.

### Task 6: Generation and spoiler log

**Files:**
